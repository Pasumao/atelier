## 目标状态

基线的笔记列表是"打开页面时拉一次"的静态快照。改造终点状态：

1. 服务端：笔记列表查询声明为 **live** 查询，失效键显式声明为 notes 表（读写两侧都可查——
   写侧端点显式声明它 emits 什么）；笔记创建提交成功后，**所有已连接的列表订阅者无需刷新
   即收到含新笔记的更新**；
2. 客户端：用户提交新笔记后，该笔记**立即**以待定状态出现在列表中（不等服务端）；提交成功后
   该项转为已确认；live 推送到达时以服务端数据为准对账（同 id 幂等合并，服务端值胜出，
   不得出现重复行）；提交失败（如输入违反契约被 ATR-201 拒绝）时，该待定项**从列表消失**、
   记入回滚名单，且错误信息（含 fix 提示）在界面上可见；
3. 失败路径与成功路径都不弄脏列表的其余部分。

## 已知陷阱（真实边界取材，非虚构）

- 失效键语法：`table:<name>` 或 `key:<业务串>`，其余形状注册期 ATR-314；显式 emits 优先于
  写侧自动表名启发式（启发式是"宁多勿漏"，冷门 SQL 请显式声明——`server/live.ts` 头注）；
- live 重算抛错推 ATR-321 error 事件但**订阅保持**（下轮写后自动重试）——别把"出错即断开
  重连"当成必要逻辑，重连语义框架已处理（重连 = 全量重算）；
- live 通道是 GET SSE；对普通端点用 GET、对 live 通道用 POST 都会被传输层拒（ATR-311 面）；
- 前端模板表达式直接调用端点方法会把 Promise 带进响应式图 → ATR-323 显式拒绝（fix 指路：
  三态原语边界消费 / live 端点订阅两条合法通道）；异步必须收敛在三态原语边界；
- 乐观对账协议的既定规则：**live 推送是真相源，乐观状态只是先行渲染**（FS-DESIGN §4.5）；
- 客户端生成 id 是本任务的合法设计（也是同 id 幂等合并能成立的前提）；服务端不生成 id
  就不会与你乐观插入的行"撞车"；**id 的 JSON 类型 = number（正整数，如 `Date.now()`）**——
  基线 notes 表主键是 INTEGER（自增），字符串 id 无法落库（`{id:"x"}` 会因类型违规被
  ATR-201 拒绝，这正是失败路径的判据载荷）；前端 optimisticList 的 id 是 string 域——
  归一（`String(id)`）后再与帧行合并是合法实现位。

## 评分驱动约定（评分 harness 按此驱动，三臂同值）

- **C 类 DOM 钩子**：列表行携带 `data-note-id="<id>"`；待定行另带 `data-pending="true"`；
  提交入口 = 一个文本 `<input>`（body）+ 一个提交按钮；回滚名单 = 带 `data-rollbacked` 的
  元素，内容含被回滚 id；错误信息（含 fix 提示）DOM 可见。
- **R 类场景形状**（mount=/api）：live 通道 = GET `/api/notes.list/live`，SSE 首连全量即时
  （首帧不计推送窗口）；创建 = POST `/api/notes.create`，成功载荷
  `{id:"<客户端id>", body:"..."}`（id = 客户端生成的正整数，JSON number）；违规载荷
  `{id:"x", body:""}` → ATR-201 四段式；写后推送断言窗口 ≤1s（自 POST 收到 2xx 起计）。
- **attempt 口径**：attempt = 应用根目录（基线装配脚本产物，已 `pnpm install`，dev.db 迁移/
  种子在账）；返工中新加依赖须自行 install。基线含 runtime 单实例化 shim（生成物 live 客户端
  与组件面同一 runtime 实例——否则信号跨实例不追踪，C 类评分假阴性）。

## 评审消歧清单（v1→v2）

1. **id 的 JSON 类型钉死为 number（正整数）**：v1 只写"客户端生成 id"，而基线表主键为
   INTEGER——字符串 id 无法落库，"成功载荷 {id:…}"的类型口径必须钉死（参考解实做发现；
   R3 违规载荷 `{id:"x",…}` 恰因类型违规被 ATR-201 拒绝，语义自洽）。
2. **推送窗口单位与起算点**：≤1s 为墙钟窗口、自 POST 收到 2xx 起计；R1 首连全量不计窗口
   （v1 只写"≤1s 窗口"未定起算点）。
3. M1 的"注册表/内省面可查"落到可机检口径（声明文本 + 注册期无 ATR-314）。
4. 新增"评分驱动约定"节（DOM 钩子 + R 类载荷/窗口 + attempt/install 口径）。
