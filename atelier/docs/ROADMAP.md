# Atelier 路线计划书（2026H2 → 2027H1）

> 版本：v0.1 草案（2026-08-30）。依据：`TECH-SCAN-2026-08.md`（市场扫描）× `BACKLOG.md`（现状）× 2026-08-30 路线定论（技能包是核心竞争力、先壮大框架功能、与 React 对照对决后置）。
> 分工纪律：**本文件只管方向与里程碑；执行队列唯一源仍是 `BACKLOG.md`**——每阶段立项时把对应条目抄送过去，完成即在 BACKLOG 归档。
> 标注约定：〔定〕= 已有决策支撑；〔议〕= 本计划书建议，待用户拍板（见 §5 决策点）；〔险〕= 风险项（见 §8）。估量沿用 S/M/L。

## 1. 定位与总目标

**定位一句话**（沿用 `TECH-ASSESSMENT.md` 定位声明，经 2026-08 扫描验证仍然成立）：Atelier 不参与"更快渲染"的主流竞赛；它下注"当编码代理成为前端第一类使用者，框架应内建契约、检视、恢复与结构公理"。

**12 个月总目标**：把经扫描确认仍无人区的四项能力做深（扁平 schema 三用 / 事务层双轨回滚 / 六层结构机检 / 可执行意图规格），用极低成本完成与开放标准的对齐拿到 40+ 客户端分发通道，用受控实验回答"技能包价值"与 Vercel 反证——最终以 v0.x 形态对外发布。

**北极星指标**（可证伪，详见 §7）：加难任务层上的 agent 首遍正确率（≥ +15pt 或绝对值 ≥ 60%）。

## 2. 现状基线（2026-08-30 快照）

**已落地**：信号内核（keyed each + Template AST 缓存）· 编译器 ②③（dump→codegen，golden DOM 对拍）· 事务层 F-1 第一期（命名合并 + patch journal + `store.graph()`）· MCP 21/21 接线 · review UI 最小版 · CI 矩阵 · 六层 struct 门禁 · checkpoint「未检不锚」· 性能四指标全达标（gzip 6.25KB / 10³ 节点 2-3ms / HMR 51ms / 截图 ~300ms）· 技能包 8 个 · M3 三臂实验（天花板效应，结论：需加难任务层）。

**明确没有**：编译期静态依赖图（F-2，决策 3 承诺）· 样式纪律第二期 · MCP 暴露 graph/journal · 标准符合性校验 · npm 发布 · 生态（路由/表单/组件库）· 跨平台 CI 实证。

**外部态势**（扫描结论摘要）：方向被 Next.js 官方背书；但 Next 16.2 / Angular v22 / Astro 7 半年内全部内建 agent 基建，agent 面已成及格线；TC39 Signals 停在 Stage 1（内核无标准取代风险）；Vercel evals 反证"AGENTS.md 优于 skills"待实验消化。

## 3. 三条主轴

1. **壮大框架本体**（F 线兑现）——编译期静态化是决策 3 的未兑现承诺，也是性能与 prod 剥离的地基；用户已定论这是主菜。
2. **深挖 agent 纵深**——在主流框架只做到"暴露运行时状态"的地方，做到"契约联动、依赖图可查、双轨可逆"；四无人区是差异化的最后阵地。
3. **标准对齐与受控验证**——标准符合性=分发通道（低成本高回报）；M3 加难实验同时回答"技能包价值"与"Vercel 反证"两个问题。

### 阶段四：公开发布与生态（2027H1 展望，不排细目）

- F-2 第二期：prod 校验剥离 + tree-shake、全量静态化。
- **npm 首发**：`atelier` 裸名可用性实测（决策 14 已留注意项）+ `create-atelier`；前置 = 性能复测 + 文档完备 + Registry 提交。
- registry-as-API / 模板分发（shadcn MCP 模式）：`app.registry.json` + starter 模板对代理可交互。
- React 对照对决（2026-08-30 定论的后置项）：视 M3 难任务数据决定是否打、怎么打。
- 社区基础设施（issue/讨论/贡献指南）：视采用情况，不预投。

## 5. 决策点（需用户拍板；本计划书不代决）

| # | 决策 | 建议 | 后果 |
|---|---|---|---|
| D-1 | 是否立项 P3-3 技能包混合实验 | 建议立项：实验不动"技能包是核心竞争力"的定论，只补数据；Vercel 反证是唯一公开的反例，回避成本高于实验成本 | 若混合更优，技能包定位从"唯一通道"调整为"渐进披露增强层" |
| D-2 | M3 加难任务层启动时点 | 建议 P1 收尾后（约 10 月）即启动，它是 P3-2/P3-3 与北极星指标的地基 | 不启动则所有正确率主张继续停在"天花板效应"档 |
| D-3 | npm 发布时点 | 建议 2027H1，不早于 F-2 第二期与性能复测 | 提前发布=生态真空暴露+支持负担；推迟=错失 agent 基建叙事窗口 |
| D-4 | D 子集适配面投入深度 | 建议只做 P3-5 预研；MCP Apps/A2UI 是 agent 当 runtime 赛道，与"agent 当开发者"主轴正交 | 深投入会分散 F 线带宽 |

## 7. 度量与可证伪指标

| 指标 | 判据 | 出处 |
|---|---|---|
| agent 首遍正确率（北极星） | M3 难任务：skill 臂 ≥ +15pt 或绝对值 ≥ 60% | SPEC §7 / M3 报告 §4 |
| 性能四指标 | gzip ≤ 30KB · 10³ 节点 ≤ 50ms · HMR ≤ 100ms · 截图回环 ≤ 500ms（当前实测全优，只防回退） | SPEC §7 |
| 标准符合性 | check-skills 对 agentskills.io 格式 100% 通过 | 扫描 §3 |
| 结构门禁有效性 | struct ERROR > 0 时全部对应真实缺陷（延续"不假红"口径） | TECH-ASSESSMENT §6 |
| 正确率主张诚实性 | 凡引用正确率必注实验档位（难任务/简单任务），禁止拿全平数据当卖点 | M3 教训 |

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| F-2 编译器改写复杂度超预期 | 〔险〕高 | golden DOM 对拍已存在（正确性锚点）；第一期只覆盖模板子集、边界内移渐进推进；fallback = 保留运行时追踪双轨，靜态图作快路径而非唯一路径 |
| 主流框架关窗（agent 面同质化） | 高 | 纵深对位：对手在"暴露状态"止步，我们在"契约联动+依赖图+双轨回滚"加码；低成本标准跟进已在 P2-2 排期 |
| M3 难任务上技能包优势不成立 / Vercel 反证被复现 | 中 | P3-2/P3-3 提前给出答案；预案 = 混合策略（内联文档为底 + skills 增强），叙事同步调整；框架本体主张（契约/事务/机检）不依赖该实验结果 |
| 生态真空 / 采用冰河 | 中 | 现实路径不变：starter + agent 代劳 + 标准分发（skills 40+ 客户端）；npm 发布前不背支持负担 |
| 单人带宽 | 中 | 每阶段出口判据硬性收口；尾巴诚实入档；阶段四之后才碰生态件 |
